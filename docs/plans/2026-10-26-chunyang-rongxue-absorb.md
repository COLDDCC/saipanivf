## 直接进入下一阶段「化」的工作单
- **H1 / 费用**：不改 `pricing.ts` 金额；只改善计算结果的状态标签和核对动作。检查相同信息在八语言的一致性。
- **H2 / 咨询**：写明“本页面仅生成邮件草稿，点击发送后仍需在邮箱中发出”；检查非邮箱联系渠道是否仍受 `type=email` 限制。优先做回归测试。
- **H3 / 流程**：审核阶段清单是否一屏可扫读、锚点可用、打印可用；真实浏览器与移动宽度取证后再决定改动。
- **H4 / 首页**：记录费用入口、流程入口、咨询入口在移动宽度的可见性、路径点击数、截图；避免对已有入口进行无意义的重造。
- **H5 / 内容**：对高风险医学判断和入境文案做逐语言证据矩阵；公开来源、适用范围与更新时间。

## 第三阶段验收方式
1. 每个变化先列出用户任务、改前任务步骤、改后目标与可观测证据；未跑测试不填分数。
2. 每批改动运行 `npm ci && npm run verify`；移动端检查宽度 320／390，桌面 1440；八语言 smoke check。
3. 医疗和入境结论的性质与来源不降低；报价仍为预算估算；咨询仍仅生成邮件草稿。
4. 保存前后截图和点击路径，明确标注“本次跑过”“历史审计”。
5. 未取得实际线上检测和 GSC 时不宣称排名、收录、转化或性能提升。
