# 春阳融雪 · Saipan IVF 第三阶段「化」（Transform）
日期：2026-10-26 · Plan 模式 · 仅定义改造，不修改站点

## 核心决策
保持原有 Astro 设计体系、多语言、SEO 与工作功能。以“可信的预算结果 → 明确下一步 → 更顺畅的咨询”为单一体验主线，不拼贴竞品的视觉组件或医疗宣传。第四阶段仅实施可测的增量改进。

## 对阶段二发现的代码复核与纠错
- **咨询联系方式切换已经存在，不应重复开发。** `src/components/LocalizedConsultation.astro` 的 `updateMethod()` 根据渠道切换 email/text、inputMode、autocomplete、placeholder；用户选择电话/WhatsApp 有专门格式校验。阶段二所列“可能受 type=email 限制”仅为待验证假设，不是确认 bug。
- **咨询邮件草稿已经有“未发送”提示。** 生成的摘要在 `f.unsent` 中，另有“打开邮件”与复制按钮；优化方向是检查用户是否实际理解两个步骤，而不是凭空增加警示文本。
- **预算误认风险已有基础防护。** `FeesExperience.astro` 显示 `budgetEvidence[locale][1]`，`LocalizedBudget.astro` 结果区包含 `b.excluded`、`b.warning`；不能声称“缺少来源声明”。
- **流程页已具备分阶段操作。** `CareJourney.astro` 包含三列“准备／确认对象／应取得结果”、六阶段导航、清单勾选、清空和打印。调整前先实测移动端。
- 具体实现风险：`budgetEvidence` 已覆盖 7 个显式 locale，简繁转换路径另需核实；静态复核不构成在线交互测试。

## 信息架构与视觉融合原则
1. **答案优先**：打开费用页后尽快能看到组合预算、排除项、书面报价核对入口。保留移动端结果先展示的现有 CSS。
2. **一条行动主线**：总览数字 → 查看组成 → 取得机构书面报价 → 需要时生成咨询邮件；不增加与这些任务无关的 CTA。
3. **统一视觉**：沿用项目 `--deep`、`--cream`、`--blue`、`--light` 的语义体系，不新增无关高饱和色；状态依靠文字而非仅颜色表示。
4. **可信分层**：明确区分计算假设、机构公开资料、机构正式确认、外部医学证据；每一种信息要用其真实状态。
5. **本地化**：复用现有翻译模块，不将中文文案硬编码到其他语言页面；保留用户当地的数字格式与语言表达。

## 第四阶段 Build 工作包（可独立验收）
### B1 费用结果聚焦（优先）
文件：`src/components/LocalizedBudget.astro`、`src/components/FeesExperience.astro`、必要时 `src/i18n/budget-evidence.ts`。
- 保留计算逻辑、原金额和既有默认选项；结果卡内增加紧凑的报价核对链接，指向已有本地化 `/guides/quotation/`。
- 将现有“非院方报价”说明在结果附近做更清楚但不冗长的呈现；避免重复免责声明墙。
- 确保动态切换 IVF/egg/FET、勾选项目后，结果及排除项不会产生误导。
- 验收：3 条路径、各种可选项目组合总额仍正确；无 JS 时可显示默认预算；八语言内容一致，键盘可达。

### B2 咨询提交预期
文件：`src/components/LocalizedConsultation.astro`、`src/data/consultation.ts`（仅在必要时）。
- 保留现有表单与邮件摘要；补强提交前后“生成草稿 ≠ 已发送”的语义，而非再造后台。
- 避免把完整敏感病历放进不安全的遥测；绝不默默发送或保存表单内容。
- 验收：email/wechat/phone/whatsapp/line/telegram 输入切换；电话校验；邮件链接与复制可用；键盘、无 JS 后备正常。

### B3 流程移动端扫读
文件：`src/components/CareJourney.astro`、`src/i18n/journey.ts`（优先调整布局，非必要不改医学文字）。
- 检查 320/390 宽度的六阶段导航和三项说明是否容易理解；如有卡点，用简短视觉层级、折叠或重点标示优化，不删除实质内容。
- 保留打印、勾选进度、清空和无长期保存性质。
- 验收：锚点与阅读顺序正确；无横向溢出；打印内容完整；减少动态效果时仍可用。

### B4 首页审查后再改
文件：`src/components/HomeDecisions.astro`、`src/pages/index.astro`。
- 只在实际截图、布局或用户任务证实存在问题后调整三入口的可见性和顺序。
- 不再新增重复费用卡或重建首屏。

## 发布前门槛
- 先执行 `npm ci && npm run verify` 建立**本轮**基线，再实施修改，变更后重跑。
- 以 320/390/1440 宽度检查简中、英语、日语及其他语言布局；保留截图与可复现任务步骤。
- 检查 canonical、sitemap、结构化数据、治疗费用算式、咨询草稿未破坏。
